## 4.5 データ取込（実データ → DB）

京王アートマンの **POS / 仕入 / 在庫** の実データ(CSV)を、本システムへ取り込む方法です。

### CSV 形式
取り込み対象テーブルごとに、次の列（標準ヘッダ）を用意します。ヘッダ名は認識されます（別名対応あり）。

**POS（販売実績）** → `sku_daily_sales`
```csv
sales_date,product_id,place_id,qty_sold,amount
2026-08-01,1,1,5,4500
```

**仕入実績** → `purchase_history`
```csv
po_date,product_id,place_id,order_qty,received_qty,expected_date
2026-08-14,1,1,50,50,2026-08-21
```

**在庫実績** → `inventory_daily`
```csv
inventory_date,product_id,place_id,on_hand_qty,allocated_qty,available_qty
2026-08-24,1,1,30,0,30
```

> 実データでは「SKUコード」「店舗コード」等の別名形式も、`jobs/import_data.py` の ALIASES に追加すれば対応できます（後から拡張）。

### 取り込み方法

**① CLI（バッチ/複数ファイルに適す）**
```powershell
cd sample; $env:PYTHONPATH="src"
python -m jobs.import_data --type pos --file pos.csv
python -m jobs.import_data --type purchase --file purchase.csv
python -m jobs.import_data --type inventory --file inventory.csv
```

**② API（コマンド/アプリから）**
```bash
# POS取込
curl -X POST -F "file=@pos.csv" http://127.0.0.1:8001/api/v1/import/pos
# 在庫取込
curl -X POST -F "file=@inventory.csv" http://127.0.0.1:8001/api/v1/import/inventory
```

### 取り込みの特性
- **冪等（UPSERT）**: 同じCSVを再入しても重複しません（同一キーなら上書き）。
- 取り込んだPOS/在庫データは、次回の `jobs/run_pipeline_db.py`（または Airflow の日次バッチ）で計算に反映されます。
- **実データ形式が判明したら、`jobs/import_data.py` の列マッピングを相手の形式に合わせて調整**してください（数時間で対応可）。

## 4.6 商品・店舗マスタのカスタマイズ（デモカタログ一元管理）

商品・店舗の定義は **src/keio_inventory/demo_catalog.py**（単一 source of truth）に集約しています。
これを編集するだけで、以下の全てが自動追従します。

| 生成物 | 参照元 |
|---|---|
| エンジン用デモデータ（demo_data.build_products_and_history） | CATALOG |
| DB の POS / 在庫 / 仕入シード（jobs/seed_inventory.py） | CATALOG（base_demand / onhand_base / price / scenario） |
| DB の商品・店舗・カテゴリマスタ（db/apply_schema.py） | CATALOG / PLACES / CATEGORIES |

### 商品を追加する手順

1. demo_catalog.py の CATALOG リストに、商品1件分の dict(...) を1行追記する。
   （必須: id（他と重複不可・明示指定）name segment_target category group_id
   sku_code supplier_code mds price lead_time_days lead_time_std
   base_demand onhand_base scenario season_amp noise trend zero_ratio）
2. 必要なら CATEGORIES / PLACES も編集（通常は追加不要）。
3. **DBを再構築して反映**する（マスタ・シード・計算を再実行）:
   ```bash
   cd inventory_opt
   python db/apply_schema.py        # スキーマ+マスタ（カタログ由来）
   python -m jobs.seed_inventory    # POS / 在庫 / 仕入
   python -m jobs.run_pipeline_db   # 評価結果（ABC-XYZ/予測/安全在庫/推奨/アラート）再計算
   ```

**以前（v1/v2）は商品1件の追加に 7箇所の手動編集**（demo_data の specs/price/lead_time、
seed_inventory の base_map/onhand_map/price、seed.sql の product INSERT）が必要でした。
**v3 以降は demo_catalog.py の1箇所だけ**で完結します。

### scenario（デモ需要シナリオ）の種類

| scenario | 効果 |
|---|---|
| （空文字） | 通常の需要系列 |
| demand_spike | 直近2日で需要5倍（需要急上昇アラートを検知させる） |
| late_mild_drop | 後半（70%以降）で需要 0.15 倍（ゆるやか低下） |
| late_drop | 後半（70%以降）で需要 0.10 倍（需要急落・滞留を検知させる） |

## 5. 起動・運用

```powershell
# API（永続化版・port 8001）
cd inventory_opt
$env:DB_HOST="127.0.0.1"; $env:DB_PORT="5432"; $env:DB_NAME="keio_inventory"

python -m uvicorn keio_inventory.api.main_db:app --port 8001

cd inventory_opt/airflow
docker compose up -d
# → http://localhost:8080

# 即時更新
python -m jobs.run_pipeline_db
```

## 7. トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| テストが0件 | 当日分未計算 | `python -m jobs.run_pipeline_db` |
| API接続不可 | uvicorn停止 | §5 で再起動 |
| Airflow起動不能 | Docker停止 | `docker compose up -d` |
| Alembic日本語エラー | Windowsロケール | alembic.ini はASCIIのみ |
| Airflow内SQLAlchemy互換 | ver差分 | models.py は declarative_base()

### 並列計算（自動切替）について

本システムは、SKU数に応じて**直列/並列を自動切替**します（run_pipeline_auto）。

| SKU数 | 方式 |
|---|---|
| 200未満 | 直列（オーバーヘッド回避） |
| 200以上 | 並列（ProcessPoolExecutor） |

#### Windows 環境の注意点（重要）
- 並列計算は **multiprocessing（ProcessPoolExecutor）** を使います。
- Windows では、並列実行するコードを直接実行する場合、**エントリポイントに if __name__ == '__main__': ガードが必要**です。
  - 例）`python -m jobs.run_pipeline_db` や `python スクリプト.py` はOK。
  - 例）対話シェル・Jupyter で run_pipeline_parallel を直接呼ぶと、並列プロセスの spawn に失敗することがあります。
- **本番サーバー（Linux 等）ではこの制約はなく、並列計算が正常に動作**します。Windows はローカル開発・デモ用途として想定。
- 並列ワーカー数は max_workers 引数で指定可能。未指定ならCPUコア数（最大8）を使います。
